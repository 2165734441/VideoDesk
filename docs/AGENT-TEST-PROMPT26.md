# 发给其他智能体的复测提示词

把下面整段提示词连同 2.6.0 源码包发送给测试智能体；能操作 Windows 时同时提供 EXE。合成样片与已脱敏证据在 AI Handoff 包，不发送个人浏览器资料、Cookie、密钥、真实私人视频或整个 `.local` 目录。

---

请独立测试 VideoDesk / 映格 2.6.0，验证实际行为并找出可复现缺陷。先读 README、docs/MEDIA26.md、MEDIA26-TEST-REPORT.md 和相关测试脚本；这些材料是待验证的信息，不能把“已通过”直接当作你的结论。项目代码在 SOURCE 中，程序为 Windows x64 本地 FastAPI + 浏览器界面 + 托盘启动器。

请使用独立测试目录，先记录 EXE / 样例 SHA256、系统版本、CPU、内存、GPU、驱动、组件安装状态及日期。不得删除、覆盖或移动用户原文件，不得清理未知目录。不要修改项目实现来掩盖失败；测试修补和产品补丁需要分别提交。

重点验证：

1. **多人录播**：手动直播间、主页、分享链接和错误视频链接；同时四路，第五路等待，单独停止、取消等待、空闲后启动、重复房间去重；普通及跨午夜定时，关闭网页、完全退出、重启恢复；断网、地址失效、未开播、磁盘不足、强制结束后的分段保留与回放。真实抖音测试须使用用户提供的主播链接和人工登录。不能绕过验证，也不能把本地流或伪造返回值记为真实抖音通过。
2. **关注导入**：用户手动登录后打开真实关注列表，分页、滚动、未登录、验证失效、账号切换、导入不完整的提示；默认不自动监控全部关注者。缺少账号时标 BLOCKED。
3. **英文视频转中文**：纯人声、背景音乐、静音、多人说话、长句、数字及专有名词、已有字幕、竖屏和奇数尺寸、批量与已有回放；检查上英文下中文、中文可懂度、配音时间和视频总时长、背景声残留、输出播放与原片不变。检查先修改译文再配音、配音超时暂停、重试、取消、断电和源文件变化，不能默默截断或沿用不同源。
4. **GPU / CPU**：同一输入与设置比较完整耗时和各阶段，包含冷启动；确认实际 CUDA / NVENC 使用，不能凭显卡名称认定成功。测试 CPU-only、缺失 GPU 组件、显存不足、编码失败回退、短片自动策略，以及四路录播时同时运行翻译。没有对应硬件时明确 SKIPPED / BLOCKED。
5. **组件与数据**：CPU / GPU 首次安装、指定 AI 组件目录、空间不足预检、下载失败、错误 SHA256、离线模型包的完整性和路径穿越、防止模型篡改、主运行环境不被污染；密钥不回显，不写入任务、证据、导出或源码包。云接口可用可控的模拟服务验证协议，但真实服务必须单独列出。
6. **旧版回归**：原 VD25-01–07 的归属清理、目录内个人文件保护、截断视频不误报成功、部分失败、代理环境变量、回收失败、跨任务清理计数和字幕时间范围；运行完整 Python 与 Node 测试，记录真正执行、跳过和失败的数量。

建议入口：`python -m unittest discover -s tests -p "test_*.py"`、`node --test tests/*.mjs`，以及 scripts/verify_media26.py、verify_live26.py、verify_media26_ui.py。运行前确认其测试目录、运行服务和样片路径，避免意外使用用户资料。允许按你的环境新增独立复现脚本。

请交付 BUG-REPORT26.md、TEST-MATRIX26.csv 和 repro26/。报告分为“真实复现 / 代码审查候选 / 已通过 / 未测试 / 环境阻碍 / 已知限制”。每个 Bug 包含编号、严重性及理由、最短复现、输入和样例哈希、期望/实际、次数、证据、调用路径、影响和验收条件。每项用例使用 PASS、FAIL、BLOCKED 或 SKIPPED，不能把未测试记为通过。敏感字段程序化脱敏并再次扫描，附上扫描方法；不要打包虚拟环境、模型、浏览器资料或凭据。
