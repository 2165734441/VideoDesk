# 映格 · 本地视频采集工作台

在网页里操作的本机工具：整合 **yt-dlp + yt-dlp-ejs + MediaCrawler + dsh-video-storyboard**，支持区域录制、定时截图、规则抽帧、编号分镜、台词对齐、照片去重和 AI 分析包。

## 2.5 独立处理流程与可恢复批次

视频抽帧默认只导出图片，AI 看懂视频自动整理“一起上传给AI”，字幕区域截图长图作为独立工具；三个流程分别保存设置，共享来源列表和保存位置。AI 附加单图、音轨和本机/缓存原片放在必需上传目录外，多视频联合资料保留分集边界。

视频检查区分路径、权限、断线、超时、编码和容器问题。网页来源按需分块读取，等待时可重新选择同一文件继续；取消后需手动重试。已完成的转写、分镜和扫描可复用。自动、低占用、均衡、高性能只调整线程资源，不减少画面与文字。

素材库支持多选清理，先预览生成文件及跳过原因，再移入系统回收站。原片、用户修改或新增文件和其他任务的共享文件保留；清理或替换任务默认隐藏，可展开查看。修复运行目录和保存目录跨盘时的批次导出与日志归档。

测试范围、同片性能比较和未复现的用户现场见 [2.5 测试记录](WORKFLOWS25-TEST-REPORT.md)。历史版本记录如下。

## 2.4 已有资料直接合并与完整性检查

分析与抽帧 → 来源选择“已有素材”，勾选多份历史资料，或导入旧素材文件夹；可调整顺序、填写集数和合集标题，再合并为一份 AI 资料。素材库也提供“加入资料合并”快捷按钮。保留原图与原文，不重新采集、不重复语音或文字识别；默认另存到顶部保存位置。支持只有“一起上传给AI”的旧文件夹，未知时长会明确标注，已知缺文件时阻止合并。新联合包可再次合并，内部保留每集分界与文件映射。

“上传文件齐全 · 共 176 个”表示需要一起上传的总数。文字置信度提示独立显示为“建议核对”，点击可查看帧号和必要细节图；有音轨却缺台词等情况另标为内容缺失。文件齐全不保证识别或采样完全准确。青绿新图标统一网页、EXE、托盘和快捷方式。

## 2.3 多链接分集导出与画面文字提速

视频链接支持逐行输入、加入队列、调换顺序，并选择每条一集、全部合为一集或自行填写集号分组。同集多视频生成本集 AI 包，也可额外汇总所有集的联合 AI 包；文件夹和包内正文均保留集号、标题、原视频与联合时间边界。合并的是 AI 资料，不拼接 MP4；不勾选联合包时按集独立导出。

画面文字默认使用平衡加速（最多两条计算线程），高级设置可改为单线程保守模式。只复用模型输入和解码参数完全一致的识别批次，不做模糊文字匹配、不减采样。每个识别进程的缓存不超过 8 MiB，进程隔离、每 24 张图回收与超时保护保留。必要原尺寸 PNG 可直接复用，避免再次编码；进度显示本阶段剩余时间。

原视频完整对照：152 个不同画面、172 张输出图像与全部文字/位置/置信度/时间轴一致，首次处理从 524.23 秒降到约 306 秒，同片复用已有文字结果约 27 秒。此结果来自同一台机器的同一视频，不能保证所有视频有相同幅度。详细记录见 PERFORMANCE-EPISODES-TEST-REPORT.md。

## 2.2.1 连续分析稳定性与文件夹导入

分析与规则抽帧页面都增加“导入本机视频文件夹”直达按钮。原生选择不复制视频；也可以使用网页选择文件夹或整夹拖入，勾选是否包含子文件夹。网页文件来源处理期间须保留工作台页面，文件内容仍按需读取。

AI 画面文字识别改为独立、低优先级 CPU 进程，单线程推理，每 24 张图释放进程；单图超时或识别组件退出时保留原尺寸画面并注明文字缺口。像素完全一致的识别结果可跨重试复用。视频解码、分镜抽图及本地语音识别降低并发，不减少既定采样画面和文字内容。任务记录写入后刷新到磁盘，并保存上一个有效版本；记录损坏时先恢复备份，再尝试从现存素材清单重建，不修改素材或原片。

此更新减少应用负载和故障影响，不能保证解决整机异常重启。Windows 的异常重启事件只确认未正常关机，不能单凭事件判断供电、温度、驱动或其他根因。

## 2.2 联合 AI 阅读包与素材管理

本机视频勾选“生成集中上传的 AI 阅读包”与“附 AI 分析索引”后，将完整台词、编号画面、画面文字及必要细节图集中放入 **一起上传给AI**。这个文件夹内的文件全部需要上传；原始索引、识别记录和可选素材留在文件夹外。新阅读包 ZIP 只包含必需上传的文件。完整台词不会按单格字数截断，长文本自动拆成连续文件。低置信度或缩小后看不清的文字会附原尺寸细节图。

多个视频可勾选“合成一个联合 AI 分析包”，按列表顺序汇总，↑↓ 可调换顺序。联合包标明每个视频标题、联合时间和原片时间，不生成合并 MP4。输出目录使用视频标题；标题中的非法字符替换为下划线，只有重名时加短标识。

高级设置中“每张拼图最多画面”支持自填整数：1 为单图，4 为每张最多四个，0 使用自动排布。超过后另起图片，最后一张允许不足。旧版每段总帧数与总拼图预算仍可能在选帧时合并镜头；需要更完整的镜头信息时将这两个总量限额设为 0。新阅读包出于可读性单张最多实际排 16 格，所有画面仍保留。

在素材库点击“选择内容再导出”，可修改分镜参数并勾选“覆盖本任务上次生成的素材文件夹”。新结果完成后才替换；旧目录已移动、文件已修改、新增或含原片时另存，不移动原片。替换前的旧版保留为可清理备份，任务上可单独清理。历史清理先列出软件记录的文件，只删除仍在登记位置且 SHA256 未变的文件，跳过已移动、已修改和已登记为来源的文件。

各项高级设置和导出选项都有小圆圈感叹号，可悬停或键盘聚焦查看说明；点击图标不会改变旁边的复选框。“硬字幕”是画进视频像素的字幕，OCR 将图中文字识别成文本；原项目的抽查校正只检查部分画面，新阅读包的文字扫描另行处理。

信息与成本取舍：默认每秒补充采样，并检测解码画面的变化，合并像素完全相同的画面引用；画面文字与口述并列保留，不凭相似哈希删除细节变化。静态采样仍可能漏掉短暂动作或文字，ASR/OCR 可能识别错误，不包含音色、音乐和每帧动作，也不能保证所有模型的 token 数最少或无损。报告列出已知缺口；有声音却没有台词会标为“需要补充”。原接口默认保留旧版行为；网页的新预设、CLI 及显式 `ai_package.enabled=true` 使用新阅读包。

CLI 可用 `batch --combined --max-cells-per-sheet 4`，`--legacy-ai` 沿用旧包，`--no-screen-text` 关闭画面文字识别。API 的 `ai_package` 字段支持 `enabled / combined / screen_text / scan_seconds / batch_files`，重新导出可传 `replace_job_id`。

## 2.1.1 登录复用与采集进度

采集记录和分析结果显示总进度、阶段、下载大小、速度与预计剩余时间；未知时长的阶段显示等待动画，人工验证时暂停。重启服务后重新读取映格专用登录浏览器的保存资料。抖音解析器失败时，读取同一目标视频的正常页面播放源，支持个人页的 modal_id 链接及 blob 播放器的正常详情响应，不自动处理验证码。普通 Edge / Chrome 与映格专用登录窗口的账号不自动共享。

## 2.1 批量导入与可选导出

本机来源在分镜分析和规则抽帧之间共享。可拖入、网页多选、用系统窗口选择多个文件、选择整个文件夹，或每行粘贴一个路径；外围双引号会忽略，空格和逗号保留。文件夹默认包括子文件夹，跳过目录联接。列表显示不可读项，可移除、追加和预览。浏览器不支持某种编码时仍可用 FFmpeg 处理，并尝试生成封面。

系统选择器与路径由后台直接读取原文件。网页文件使用 File.slice、1 MiB 块、带会话验证的 WebSocket 和仅监听回环地址的 HTTP Range 通道；不上传完整视频，也不在磁盘缓存原片。处理网页文件时保留工作台；来源断开后任务进入“等待来源”，释放处理队列。重新选择同一文件（核对名称、大小、修改时间及首尾摘要）后，从未完成的时间段继续；素材库也可直接重新选择并继续。

导出可独立选择单帧图片、音轨、拼图、台词、分段小视频；快捷选择仅图片 / 音轨 / 拼图 / 台词或 AI 分析包。默认 AI 包包含拼图、对齐台词和索引。纯素材输出目录只包含所选类型，处理记录和中间单图存放在应用资料目录，可另勾选 ZIP。仅音轨不会抽帧或转写；仅台词不会抽帧；仅拼图仍按当前台词来源将文字与画面对齐。

“导出图片去重”默认关闭；完全相同使用内容指纹，相似比较复用 ImageHash，保守 / 适中 / 宽松阈值为 4 / 8 / 12，自定义 0–16。只去重导出的单帧图，保留中间原图，不删除拼图和台词。阈值越高越可能合并字幕细微变化。

分段默认关闭，开启后默认每段 10 秒；“分段小视频”与“按段整理素材”分别控制。小视频重编码为 H.264 / AAC，保留原尺寸和不足一段的尾部。各类素材使用相同边界；字幕同时提供原视频时间与片段内时间。文件夹为 `批次 / 视频名_短标识 / 片段 / 素材类型`，不开启分段则省略片段层，不按段整理时给文件名前加片段编号。

单个失败不会阻断其他视频，可单项或整批取消 / 重试。完全没有所选内容时显示原因并报失败；没有音轨或台词不输出伪空文件。提交带请求标识，同一请求重试复用任务。连接中断时保留表单，点击重连；旧地址失效时从托盘重新打开。

CLI 示例（多个路径各自加引号，路径内部空格保留）：

```powershell
VideoDesk-2.1.0-Windows-x64.exe --cli batch "D:\视频\商品 A.mp4" "D:\视频\商品 B.mp4" --outputs frames,audio --segment 10 --dedup 4
VideoDesk-2.1.0-Windows-x64.exe --cli batch --folder "D:\视频" --outputs clips,frames --segment 10
VideoDesk-2.1.0-Windows-x64.exe --cli export 任务ID --outputs audio --output "D:\素材"
```

支持 `--paths-file` 导入 UTF-8 多行路径、`--no-recursive`、`--frame-mode seconds|fps|frames|all`、`--frame-value`、`--request-id`。API 为 `/api/sources/register`、`/discover`、`/browser`，`/api/batches` 和 `/api/exports/{任务ID}`；旧单视频 API 继续可用。新增 DSH 工具 `video_desk_batch` 与 `video_desk_export`。验收细节见 `BATCH-TEST-REPORT.md`。

## 2.0 合并版

主导航收拢为“导入与采集”“分析与抽帧”“素材库”“账号与模型”。原来的框选录制、全部规则抽帧、去重隔离与恢复均保留。按钮增加悬停、按下和提交反馈。

分镜采用 SAOS-3624 的镜头检测、积分取帧、按切换密度分档和行打包算法。保留五档策略、三种选帧方法、长视频分段、帧数和页数上限。每格对应原视频时间、台词与高清单图；上限可能导致合并镜头，实际计划写入 evidence.json。

字幕优先使用导入 SRT/VTT/JSON、平台字幕或嵌入字幕，再选 ASR。设置页可一键安装 SenseVoice（约 155 MB，中英日韩粤），也可导入 / 导出官方离线包。OCR 模型已内置 EXE。语音识别会听错专名，时间为近似句子范围；支持术语替换表，或选择自行配置的兼容 ASR 服务和热词。

硬字幕保留手动框选规则抽图，新增手动 / 自动字幕带长图、时间索引、可选 OCR 和 ASR 抽检校正。采样可能漏掉间隔内的字幕。

在线可选缓存分析、直接读取不保存视频。直接模式经本机内存转发，不落盘视频或分段；细看时重新解析来源，不自动切换成下载。缓存位置、用量和清理入口在设置中。本机原片直接读取，只有明确勾选导出视频才复制到 ZIP。

结果页支持按台词查找、选分镜格或指定时间细看。AI ZIP 默认含拼图、清单、完整台词、索引、参数和提示词，可附高清单图、音轨、已有视频。通用导出不采用 DeepSeek 固定视觉 token 估算。

## EXE 一键启动与分享

推荐发送 `release/VideoDesk-2.1.0-Windows-x64.exe`。接收者双击自动部署并打开网页，无需预装 Python、Git、Node.js、FFmpeg。首次释放组件可离线；语音模型首次下载和访问平台需要网络。离线转写可同时发送 `SenseVoice-offline.tar.bz2` 并在设置中导入。详见 `EXE-README.txt`。

它使用官方 Python 3.13.17 嵌入式发行版和两套隔离的依赖目录，内置 Node.js、MediaCrawler 固定源码和备用浏览器，因此接收者无需运行 Git 或 pip。该版本已验证现有两个引擎与 Python 3.13 的兼容性。

默认安装在 `%LOCALAPPDATA%\VideoDesk`，默认素材位于当前用户文档中的“映格素材”。资料与版本目录分开，不带入发送者的账号或视频，不修改系统 PATH。首次完成后尝试创建桌面快捷方式，后续启动复用已有环境。支持 Windows 10 / 11 x64，建议预留 3 GB 空间。

就绪后启动窗口自动隐藏到系统托盘，任务栏不留最小化窗口。双击托盘打开工作台，右键查看状态、打开保存目录或退出；关闭状态窗口只隐藏。关闭网页不结束本机路径或在线后台任务；网页 File 来源会暂停等待重新选择。录制时必须保持采集页面存活并先停止保存。后台异常退出有通知与重启入口。源码启动不带 EXE 托盘。

## 源码版启动

当前电脑已安装两个引擎及其独立环境。双击 **`start.cmd`**，在 Edge 中打开工作台：

**http://127.0.0.1:18966**

`stop.cmd` 关闭此工具的后台进程。停止前先在工作台“停止并保存”录制，等任务完成。不要直接关闭正在采集的网页。

更换电脑 / 重新安装时：先安装 Python 3.12、Git、Node.js 及 Edge 或 Chrome，双击 `install.cmd`。MediaCrawler 的 pandas 等依赖使用单独的 Python 3.12 环境，与主工具环境隔离。也可以指定 Python 路径：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1 -CrawlerPython 'C:\Python312\python.exe'
```

遇到端口占用或 Windows 端口保留，指定其他端口：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Port 18967
```

1. 在普通 Chrome / Edge 中登录平台并打开视频。
2. 在同一浏览器的另一个窗口打开本工具；在顶部选择保存目录，点击保存设置。
3. 点击“选择视频标签页 / 窗口”，在浏览器提供的对话框中选择平台标签页。需要声音时勾选“共享标签页音频”。
4. 在预览画面中拖动框选，整个画面则不框选。
5. 选择录视频、截图或同时进行，设置频率、自动停止秒数、图片上限，开始采集。
6. 遇到人机验证或登录弹窗时，暂停采集，自己处理后继续。暂停时间不计入采集时长。
7. 点击“停止并保存”，在素材列表查看 WebM、可选 MP4、音轨与截图。

首次共享必须由你在浏览器对话框选择来源；浏览器不允许网页无提示自动取得屏幕。每次录制可以设置时长自动停止。需要批量处理多段视频时用链接下载 / 平台采集。

**采集期间让工作台保持可见，建议与视频窗口并排显示。**浏览器后台节流、系统锁屏、窗口最小化、系统性能等可能影响画面 / 截图频率，实时模式不保证逐帧精确；需要准确的逐帧拆解，请先下载或录制完成，再用视频直接抽帧。

截图频率：实时采集最高每秒 10 张；离线按秒采样支持每秒最多 60 张；“每一帧”和“每隔 N 帧”按视频原始解码帧处理，不受 60 张限制。帧数仍受你设置的数量上限约束。

## 登录、验证与两个引擎

- 下载 / 平台采集页面的“登录”按钮会启动本工具专用的可见 Edge / Chrome。登录由你手动完成，资料保存在 `.local/browser-profile`。
- yt-dlp 在下载开始前读取该浏览器中对应网址的 Cookie；临时 Cookie 文件使用后删除。它不会自动读取你平时使用的浏览器资料。
- MediaCrawler 优先使用本工具登录浏览器中对应平台的 Cookie；也可在其采集浏览器中手动登录。该浏览器的持久资料在 `.local/crawler-browser-dy` / `.local/crawler-browser-bili`。
- 两个引擎共享任务与输出管理，但不共享正在打开的浏览器资料目录，避免文件锁冲突。
- 不自动处理验证码。平台验证、登录状态、视频是否下架和账号权限均影响下载；失败时可手动完成验证后重试，或使用网页播放录制。
- MediaCrawler 捕获可识别的风控 / 验证错误时，会保留采集浏览器并将任务标记为“待人工验证”。你手动处理后点击任务中的“已完成验证，继续”，引擎刷新登录资料后重试；未识别为验证的网络或平台错误仍会报告失败。不会自动点击或破解验证码。
- MediaCrawler 按页查询搜索结果，但本工具对媒体下载尝试数量设定上限；到达上限后停止后续翻页。作者模式也受限制。一次最多设置 50 个视频。
- MediaCrawler 和下载 / 抽帧各有独立的串行工作队列，等待登录时不会阻塞本地抽帧。关闭浏览器会导致当前平台任务失败，任务页会提示重试。

## 给 AI 的素材

每个任务在保存目录中建立独立子目录，包含相应文件：

```text
20261026-xxxxxx_任务ID/
  video.mp4 / recording.webm / recording.mp4
  audio.m4a
  frames/000001.jpg ...
  timeline.json
  manifest.json
  AI分析提示词.txt
```

MediaCrawler 的原始视频在其 `dy/media/作品ID` 或 `bili/media/作品ID` 等上游目录内；自动抽帧作为独立任务出现在列表中。

`timeline.json` 中：离线抽帧的 `seconds` 是原视频时间戳（变帧率视频也从解码日志读取）；实时采集是去掉暂停后的采集经过时间，**不等于播放器显示的播放进度**。不要混用两者。

2.0 可进行本地语音转写和台词对齐，准备分析素材后由你交给支持这些输入的 AI。它不会自动向聊天模型上传视频。没有可用台词时，导出提示词明确说明缺少语音信息。

## 本机数据

- 默认保存位置：项目的 `output` 目录。顶部可输入完整路径或选择任意有写入权限的本机目录。
- `.local/settings.json`：保存位置设置。
- `.local/jobs.json`：任务记录；重启后未完成任务标记为中断，已保存文件保留。
- `.local/server.*.log`：本机服务诊断。
- `.local/crawler-任务ID.log`：上游采集诊断；仅在本机，不自动上传，不作为 AI 素材展示。分享日志前请自行去掉个人信息。
- 登录资料只在本机保存；不要公开 `.local` 目录。服务仅监听 `127.0.0.1`，修改请求要求本机会话令牌并检查来源。
- 不覆盖你已有的素材；每次任务创建独立目录。当前不提供无人值守账号轮换、自动破解验证、付费访问绕过或整站镜像。

## 照片与截图去重

1. 左侧打开“照片与截图去重”，选择本机文件夹或已有素材任务。素材列表也提供“图片去重”快捷入口。
2. 默认使用 SHA-256 识别文件内容完全相同的图片。选择“相似图片”可识别部分压缩、缩放后的副本或连续截图；宽容度越大，候选越多。图片在本机处理。
3. 预览重复分组，点击缩略图可打开原图核对字幕等细节。默认推荐分辨率较高的一张，可改选保留项，或取消处理整组。
4. “导出去重副本”会保留所有未重复图片、每个勾选分组的保留项以及未勾选分组的全部图片，复制到报告目录的 `unique-*` 文件夹，保持相对路径，原图不变。
5. “将重复项移入隔离区”只移动勾选分组的重复项，保留项不动。隔离目录为原图片目录内 `.video-desk-quarantine`（隐藏目录），可点击“恢复隔离图片”撤销；恢复遇到同名文件会停止，不覆盖新文件。不要手动清空隔离区或删除去重报告，否则无法通过页面恢复。
6. 扫描后图片发生变化会拒绝处理，需重新扫描。取消或关闭程序可能留下部分已完成操作，隔离操作会逐文件写日志，可从原记录恢复。达到扫描上限时只处理已扫描图片，请分批或提高上限。损坏图片、隐藏目录、符号链接和目录联接不会用于判重。

相似图基于开源 [ImageHash](https://github.com/JohannesBuchner/imagehash) 4.3.2 的 pHash + dHash，并核对颜色和比例。它寻找视觉相近的候选，不能保证字幕、数字或所有细节完全一致，请审核后处理；动画只按文件内容判重。许可证见 `third_party/ImageHash-LICENSE.txt`。测试增加了识别、导出、隔离、恢复、文件变化与覆盖保护，以及完整 HTTP 接口流程。


## 直接抽帧与 YouTube（1.3）

- **视频直接抽帧 → 本机视频**：通过“选择本机视频”或填写完整文件路径直接读取原文件，不上传、不复制、不修改；支持视频预览、框选区域及全部抽帧设置。
- **视频直接抽帧 → 视频链接**：每行粘贴一个 YouTube、抖音、B 站或其他 yt-dlp 支持的视频网址。由 yt-dlp 仅解析地址，FFmpeg 直接读取视频流并输出 JPG；不先下载视频、不写入视频片段，不会在失败后偷偷切换为保存视频。
- 支持每 N 秒、每秒 N 张、每隔 N 帧或全部帧，以及起始时间、时长、上限、按百分比裁剪；在线模式默认不保存音轨，可自行勾选。
- “批量链接下载”同样提供“直接抽帧，只保存图片，不保存视频”选项；不勾选时仍按原方式保存视频，可接续抽帧。YouTube watch、Shorts、youtu.be 分享链接由官方 yt-dlp 解析，支持专用浏览器手动登录。当前按单个视频处理，纯播放列表仅取第一条。
- YouTube 使用 GitHub 上的官方 yt-dlp 与 yt-dlp-ejs 0.8.0，并显式启用 Node.js（22+）；EXE 已内置匹配的脚本与运行时，不依赖首次运行联网获取组件。源码方式请安装 `yt-dlp[default]`（见 requirements / lock）及 Node.js 22 或更新版本。
- 直接抽帧仍需读取视频数据、消耗网络流量。程序沿用现有系统 HTTP 代理（含 Windows 代理），不更改系统设置；本机回环源直接连接。其他代理类型、仅提供特殊分段列表、直播或受限的视频可能不适用，可选网页定时截图。登录和人机验证由使用者手动完成。
- 报告包含视频公开元数据、截图原视频时间索引、分析提示词及可选音轨；不保留签名 CDN 地址或请求 Cookie 到报告、FFmpeg 日志中。兼容“上传视频”方式仍会保留视频副本，页面已明确区分。
