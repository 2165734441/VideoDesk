# 拔掉数据线也能自动录（2.9.1 / 2.9.2）

手机伴侣原本靠 USB 的 `adb reverse` 把手机的 `127.0.0.1:47631` 转发到电脑。
拔线后这条转发消失，手机就再也收不到“开播了，开始录”的指令 —— 检测还在电脑上跑，
但手机录不了，等于白等。2.9.1 把这条通道改成**USB / Wi-Fi 双通道**，手机只认
`127.0.0.1:47631` 这个地址，电脑负责保证它一直通。

## 怎么用

1. 手机用数据线连电脑一次（同一 Wi-Fi），点工作台「手机伴侣 → 连接已安装的手机」。
2. 连接后电脑会自动执行 `adb tcpip 5555`，把手机的调试端口开在 Wi-Fi 上，并把转发改到
   Wi-Fi 通道。状态行会显示「手机已连接 · 无线 192.168.x.x · 拔掉数据线仍会检测和录制」。
3. 之后随时可以拔线。检测、录制、回放传回电脑都继续走 Wi-Fi。
4. 想手动重开：点「开启无线（拔线也能录）」。

没 Wi-Fi 或路由器开了设备隔离时，无线会接不通，程序自动留在 USB 通道，不影响有线使用。

## 实现要点

- `integrations/mobile.py`
  - `enable_wireless()`：读手机 wlan0 地址 → `adb tcpip 5555` → `adb connect` → 校验
    `get-state` → 记住地址（`credentials/mobile-pair.json`）→ 重建反向转发。
  - `preferred()`：Wi-Fi 能答就用 Wi-Fi，否则退 USB；反向转发只保留一条，避免两个通道
    抢同一个手机端口。
  - `keep_link()`：每 6 秒巡检。发现“当前转发走 USB 但 USB 设备已经不在列表里”，立刻
    把转发搬到 Wi-Fi —— 不用等手机先失联，换线空窗从 25 秒级降到 1 个巡检周期。
  - `wifi_address()` / `mdns_wireless()`：手机 DHCP 换了 IP 也能靠 `adb mdns services`
    按设备名重新找到，不用重新插线。
  - `devices()`：同一台手机的 USB 与 Wi-Fi 两个 transport 只显示一条，配对面板不会
    再问“你要连哪一台”。
- `static/media26.js`：手机伴侣面板新增「开启无线（拔线也能录）」按钮，状态行直接显示
  当前走的是无线还是 USB。
- 手机端 App 不用改：它一直只认 `127.0.0.1:47631`，通道换了它无感。
- 2.9.2 补列表可见性：自动检查类任务在没有本地文件时会被 `listed_jobs()` 过滤，而手机录制
  不落本地文件，结果“明明在录却一张卡都没有”。现在手机确认开录后写入 `phone_recording`
  标记，列表保留这张卡并显示「手机正在录制」；录制结束、切回电脑或出错时清除标记。

| 21:31 | 升级 2.9.2 后看任务列表 | 出现「胡说老王 · 直播录播 · 手机正在录制」，`phone_recording=true`（修复前同一状态被过滤掉） |

关键结论：**拔线只断 USB transport，Wi-Fi transport 和手机端的录制线程都不受影响**。
21:05 之后手机的整条桥（配置轮询、状态上报、回放上传）已经跑在 Wi-Fi 上，USB 通道
处于空闲状态 —— 此时拔线不会再影响任何一环。手机录制本身是 `StreamService` 里的独立
线程 + 前台服务，本来就不依赖电脑在线；2.9.1 补的是“电脑还能把开播指令送到手机”这一段。


## 边界

- 手机和电脑要在同一个局域网，路由器不能开 AP 隔离。
- 手机重启后 `tcpip 5555` 会失效，需要再插一次线（或重开一次 USB 调试）。
- 无线调试会让手机多一条“USB 调试已连接”通知，属正常现象。
- 手机录好的文件仍然先落在手机；重新连上（USB 或 Wi-Fi）后自动分段传回电脑并校验
  SHA256，原件保留在手机 `Movies/VideoDesk`。
