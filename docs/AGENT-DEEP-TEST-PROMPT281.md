### 3. 执行方法与深度要求

先做安装启动冒烟，再测 A～E 关键录播链路，随后覆盖其他模块。每个关键链路至少覆盖正常完成、非法/边界输入、失败恢复、重复操作/并发四类行为。先完成一条端到端闭环，再扩大输入组合。

不能只测接口：必须像普通用户一样通过界面执行添加、开始、停止、传输、查找回放、播放和拖动；结合 UI、服务状态、实际文件、解码结果交叉验证。接口成功、按钮变色、进度 100%、文件非空、存在 AAC 音轨，都不能单独证明成功。

边界使用等价类与相邻值；并发检查开始/停止、解析回调、重连、配置更新和导入完成的交错顺序。缺陷通常复现至少两次，记录失败次数/总尝试次数；间歇性问题如实保留首次证据，数据破坏问题不要为凑次数反复执行。

不设必须发现多少 Bug、固定通过率或虚假用例配额。深度取决于实际覆盖、故障恢复和证据质量。无法完成的项目列为 BLOCKED/SKIPPED，写清前置条件和剩余风险，继续完成其他可执行项目。

### A. 直播身份、关注数量与主播管理【最高优先级】

1. 分别输入公开直播间链接、主播主页、短分享链接、带文字分享、前后空格/换行/查询参数、相同链接的不同形式。覆盖非法网址、伪装域名、无主播主页、不开播主播。检查解析结果、去重与错误提示。
2. 核对 webRID、19 位原生 room ID、secUid 的语义与字符串精度；数字恰好相同也不能没有身份依据就合并。相同主播不同合法链接应去重，同名不同主播不能合并。
3. 故意提供含目标主播与其他推荐主播、嵌套 owner、拆分/转义 RSC 数据的受控页面。确认录制始终属于用户选择的主播；打不开目标时不能录推荐直播充数。合成页面验证与真实平台验证分开记录。
4. 测试备注留空、重命名、长文本、中文/emoji、HTML 特殊字符；备注不是唯一身份。已导入关注项被选中后不应再次强制填写同一链接；只输入昵称时应说明如何定位。
5. 关注列表验证多页、重复页、中断继续、页失败、换号、登录过期、延迟到达的旧账号响应。人工查看与同一时刻返回数据交叉核对，不把推荐列表或历史账号条目计入。
6. 核对已读取数、平台已知总数、差额及“完整性未确认”；总数未知、总数小于已读、最后一页单独到达时，不能假报完整或显示负差额。平台不可见账号与软件漏页分别分析。
7. 修改已有主播链接、备注、设备目标、定时策略后保存/重启；检查新设置生效、旧缓存失效，且不影响其他主播。

### B. 电脑真实直播录播与回放【最高优先级】

1. 找一个当前确实开播、允许测试的公开直播间，用普通用户流程：添加→检测→开始→观察持续写入→停止→完成封装→回放列表→播放/拖动/听声音。历史链接 `https://live.douyin.com/667494621873` 可尝试，但它此刻可能未开播；不得把历史在线当作当前在线。
2. 优先选择公开教学类主播；不可用时换另一位并记录理由和身份，不长期反复请求已失效地址。保存测试时刻的最小身份证据、实际流/回放关联，隐藏签名参数。
3. 覆盖至少两路不同主播真实并行；资源允许时测试当前配置并发上限、上限前一位、达到上限及超出一位，确认队列与提示符合设置。停止其中一路，其他路应继续增长，名额正确释放。同一主播重复点击不能失控启动多个任务。
4. 测试未开播、下播、重开、流地址过期、403/429/验证页、DNS/网络失败、短时断网恢复；未知不能被标记为明确未开播或已开播。平台限制与程序错误分别记录。
5. 解析中停止、连接中停止、录制中停止、封装中重复停止、开始后立刻取消、停止后迟到回调，不能出现“已停止却再次启动”、孤儿 FFmpeg 或无限重试。
6. 测定时录制、北京时间跨午夜、窗口外不自动启动、重启恢复、分段连续性、输出目录切换、跨盘保存、不可写目录及受控空间不足；全局目录与单主播覆盖设置应一致且可解释。
7. 对成片执行 ffprobe、完整音视频解码及人工回放；核对时长、帧数、尺寸、音轨、声音实际可听性、音画同步和尾段。损坏/部分保存必须如实显示，不能假报完整成功。

### C. 手机多主播独立录制与备用录屏【最高优先级】

当前目标能力：最多四路独立 H.264/AAC FLV 网络流，保存为 MP4；单屏 MediaProjection 是另一种备用方式，只能采集一个屏幕。旧文档“手机只能一路”不能用于否定当前独立流四路能力，也不能把切屏录一个显示画面当作多路独立录制。

1. 真机从电脑发起和手机按钮发起分别跑通：解析准确主播→状态进入录制→字节与时长持续增长→停止此主播→封装→手机播放。检查当前主播匹配、画面内容及声音，不只检查状态字符串。
2. 分别测试 1、2、4 路不同真实主播同时录制及第 5 路请求；超过容量应有明确处理，不能隐性超额、覆盖旧文件或把等待解析当作已录制。没有四个真实在线源时四路用例标 BLOCKED，受控四路测试只能作为补充。
3. 多路期间切换选择、打开其他网页、返回桌面/后台、锁屏再解锁，确认每一路仍对应自己的源。停一路后至少观察其他路持续写入，再增加新一路；停止全部应逐路封装完毕，状态不残留。
4. 快速重复开始/停止、同一主播别名重复开始、同时来自电脑与手机的命令、解析超时后回调、排队时停止、链接被修改、离线命令迟到，均核对唯一任务与最终状态。
5. 覆盖未登录、验证码、空白/小窗口页面、重定向、主页转直播、慢页面、无兼容流。当前解析页面应有正常完整窗口；不要绕过验证，也不要偷偷切到推荐主播。
6. 手机短断网、Wi-Fi/移动网络切换、流结束、重试耗尽、服务器不提供兼容编码等场景，记录每路错误与重试次数，检查一路失败不会终止其他路。手机独立流应使用手机网络，不能依赖电脑代录再冒充手机录制。
7. 测手机本地可写空间不足阈值前后、30 分钟分段边界、后台进程被系统终止后重开、临时 FLV 恢复。原始片段恢复失败应保留，不能删除后仍称保存成功。
8. 备用屏幕录制分别验证授权允许/拒绝、单应用/整个屏幕选择、等待授权时取消、授权后立即停止、通知停止、电脑停止、内部音频可用/不可用。系统授权由用户操作，报告记录实际选择。
9. 独立流和屏幕录制同时请求时，按实际设计核对冲突处理、资源、停止按钮与文件归属；不能让一个“停止”误杀所有非目标录制。
10. 记录权限变化、后台服务通知、电池策略、系统资源限制。Android 15+ 后台 dataSync 服务累计时限可在受控测试手机上按官方受支持测试方式验证；未实际跨越时限或执行对应故障注入，不能声称已测通。

### D. 手机录完→USB 回传→电脑回放【最高优先级】

1. 连着 USB 录完自动传回、手机离线录完再接线、伴侣重开后传回、电脑重启后重连分别实测。核对手机原件、电脑保存位置、回放入口和素材列表，原件不应因成功传输被删。
2. 至少一次在真实传输中物理拔线，再接线并等待恢复，记录断点与最终哈希。仅删除/恢复 ADB reverse 的实验要明确标成桥接模拟，不能写成已实际拔线。
3. 传输中分别重启隔离电脑服务、手机伴侣，验证已收字节/偏移持久化，不无限归零、不产生第二个任务。大文件使用允许测试的自制媒体，不能修改用户录制。
4. 两路或多路先后/同时完成，重复点击“传回电脑”、重复发送完成回执、重连后重发，检查导入幂等：一份手机文件只对应一个最终任务；重名不同内容不能覆盖。
5. 对每份实测文件记录手机/电脑字节数与 SHA256，要求一致；电脑还要校验视频轨道、完整解码并从真实 UI 播放、拖动、听声。网页媒体请求核对 Range 206/边界处理，HTTP 200 或 MP4 文件头不算完整成功。
6. 自建无害上传样例测试错误鉴权、错误/旧配对密钥、错误 offset、重复块、越界块、超长 JSON/块、尺寸不符、错误 SHA、截断文件、非视频、同名文件、重放回执。确认拒绝不会损坏有效断点或导入其他内容。
7. 在测试卷模拟写入失败、空间不足、最终重命名/校验失败、完成后响应丢失。已校验文件与临时 `.part`/导入中任务的状态必须一致，重试可恢复，清理不能删除进行中的导入。
8. 导入位置遵循实际保存设置；更换全局目录后再次导入并重启验证。错误路径、路径穿越和非常长文件名不得写到 QA 根目录之外。
9. 手机/电脑断开时界面如实反馈，连接恢复不需要反复重装 APK。未连接时的录制命令不能谎报执行成功，过期/重复命令不能再次启动录制。

### E. 手机与电脑主播同步、离线编辑【最高优先级】

1. 电脑修改已有同 ID 主播备注、链接、目标设备与设置，手机应更新对应字段；只改备注保留正确身份，换链接不能复用旧主播原生 ID。
2. 手机离线新增主播，重连后本地未同步项不丢；手动同步可上传并按稳定身份/合法 URL 去重。重复同步、重启及同名不同主播分别验证。
3. 离线新增后保持输入框中有未提交内容，接 USB 并等待至少三个实际配置轮询周期；输入内容、光标及选择不得反复被刷新重置。保存后再核对电脑和手机最终配置。
4. 双端同时编辑同一条目、删除后迟到响应、禁用监控、窗口外事件、旧账号/旧会话消息，验证明确合并或冲突行为，不“复活”已删除任务或错误录制。
5. 开播通知/检测事件分别选择电脑录制、手机录制、忽略；重复点击、事件过期、手机离线、主播已被禁用时验证去重及执行对象。通知昵称不足以证明唯一主播身份。

### F. 英文视频→中文字幕、中文配音与成片

1. 使用可再分发或合成样例建立简短英文、长句、静音、背景音乐、多人交替、口音/噪声、竖屏和可变帧率集合。记录原片 SHA256 与参数，人工核对一部分转写/翻译内容。
2. 完整执行识别→翻译→编辑→双语字幕→中文配音→成片。英文在上、中文在下；字幕换行、字体、时间轴、长句、首尾边界及视频边缘可读性正确。
3. 配音确实是可听懂的中文，检查漏句、重句、截断、静音、越界、口型/语义时间对应，以及配音与背景音/原声保留选项。存在音轨不能代替听音。
4. 修改识别文本与翻译后重新合成，应使用新内容；多任务并行、失败重试、取消后重启不能串用其他任务的字幕/音频、旧缓存或覆盖原片。
5. 覆盖导入 SRT/ASS、编码/时间轴错误、字幕优先策略、无字幕视频、组件/模型缺失、下载中断、离线包损坏及断网。不能以静默空结果宣称成功。
6. 默认本地流程的素材不应未经配置外发。显式选云服务时用测试凭据，验证错误提示、超时与凭据脱敏；不使用用户付费额度做无界压力测试。

### G. CPU/GPU 性能、回退与资源泄漏

1. 分别记录 ASR、翻译、背景分离、TTS、视频编码的实际后端。当前不是所有步骤都支持 GPU；直播直接存流通常不需要显卡。区分“可选”“配置启用”“实际执行”，以日志和实际资源使用交叉验证。
2. 同输入、参数、模型与质量要求比较 CPU 和实际可用 GPU，分别记录下载、冷启动、热启动、各阶段与端到端耗时；条件允许重复三次报告每次值和中位数，不能用不同质量输出宣称提速。
3. 测无独显/无 CUDA、显存不足、GPU 初始化失败、硬件编码 probe 失败、CPU 回退，产出仍应可用且状态真实。NVENC/QSV/AMF 名称出现在配置里不等于实际可编码。不得卸载驱动制造失败。
4. 观察连续启动/停止、取消/重试、反复开关页面、手机反复解析、导入完成后的 CPU/内存/句柄/线程/文件描述符、磁盘增长及孤儿进程。区分模型常驻缓存与持续无界增长。
5. 大任务+多路录播+手机导入同时进行，测 UI 响应、停止可达性、进度更新和音视频完整性；资源压力要有上限，达到预设阈值停止并保留证据。

### H. 原有视频工作流、文件保护与任务恢复

- 样例覆盖极短/零字节/损坏媒体、奇数分辨率、横竖屏、可变帧率、无音轨、多音轨、中文字幕/英文字幕、中文/空格/emoji/逗号路径、长路径、重名文件、跨盘和不可写目录。

### J. 长时间测试与真实能力边界

至少安排一次跨过 30 分钟分段边界的真实或明确标注的受控持续录制，核验片段前后画面、声音、时间连续性、命名、传输与回放。条件允许再执行两小时组合稳定性测试：多路录播、配置轮询、停止/开始、USB 重连与回放交错进行。

记录实际起止时间、每路字节/状态采样、资源曲线、片段数量与失败恢复。用户时间、源站下播、设备或运行预算不允许时写明已运行时长及未覆盖边界；不要用缩短常量、只等待几秒或 mock 定时器冒充真实 30 分钟/两小时/系统六小时测试。加速注入可以单列，不能替代真实时长证据。

测试结束核对：本轮录制均停止、媒体已封装或明确保留恢复片段、没有孤儿进程、没有未完成导入、用户原数据未改变；只关闭自己启动的进程。测试证据保留，不擅自删除应用旧版本或清理用户磁盘。

### 4. 源码自动化与补充复现

有源码时先阅读 `docs/BUILD.md` 和测试文件，使用独立依赖环境与数据目录。运行当前完整 Python/Node 测试集，发现未覆盖的重要边界可新增独立复现脚本；原有测试通过不能代替真机/真实媒体测试。

PowerShell 示例，先将 `$qaRoot` 指向你新建的绝对 QA 目录，且确认当前目录为目标源码副本：

```powershell
# 使用已经创建好的 QA 根目录；不要复用正式应用的数据目录。
$env:VIDEO_DESK_DATA = Join-Path $qaRoot 'source-data'

# python 应来自你的测试依赖环境；保存完整输出和立即取得的退出码。
python -m unittest discover -s tests -p 'test_*.py'
$pythonExit = $LASTEXITCODE

# 显式展开文件，避免 shell/Node 版本不同导致通配符漏跑。
$nodeTests = @(Get-ChildItem -LiteralPath '.\tests' -Filter 'test_*.mjs' -File |
    Sort-Object Name | Select-Object -ExpandProperty FullName)
if ($nodeTests.Count -eq 0) { throw '未收集到 Node 测试，不能报告通过' }
node --test @nodeTests
$nodeExit = $LASTEXITCODE
```

DSH 集成需要 `VIDEO_DESK_URL`、`VIDEO_DESK_TEST_VIDEO`、`VIDEO_DESK_TEST_OUTPUT` 指向已确认的隔离实例、合成视频和 QA 输出目录。缺前置条件跳过时披露原因；条件补齐后单独重跑，不把 SKIP 计入 PASS。保存运行器实际收集数、PASS/FAIL/ERROR/SKIP、退出码和耗时，不预设“应该有多少项”。

不要盲跑 `.local/`、旧 `repro/` 或 `scripts/verify_*` 中的历史脚本，它们可能绑定正式数据、旧版本、真实设备或特定主播。先检查副作用，改用自己的参数和夹具。新增 harness 必须校验产品实际输出，不能仅验证自己写的 mock 或复制实现逻辑后互相证明。

音视频可使用发布包内或测试环境已存在的 ffprobe/ffmpeg。记录绝对工具路径与版本；对选定实测成片执行等价的完整解码检查，例如 `ffmpeg -v error -i <测试文件> -map 0:v:0 -map 0:a? -f null -`，保存退出码与 stderr，并加人工播放/听音。保护路径与参数引用，不拼接未经处理的命令文本。

### 5. 判定规则

- `PASS`：本轮在明确构建/环境下实际执行，结果符合合理预期，有证据。
- `FAIL`：已观察到产品行为不符合明确预期；指出影响及关联 Bug。
- `BLOCKED`：缺硬件、账号、权限、在线源、依赖或平台阻挡，无法作出产品通过/失败判断；写阻碍与已尝试步骤。
- `SKIPPED`：未执行或主动暂缓，说明原因与风险。状态未知、只读代码、历史通过均不能填 PASS。

纯代码风险单独列“代码审查候选”，不能混入已复现 Bug。单元/受控夹具复现可以成立，但必须明确层级，不能写成真实平台/真机端到端已经复现。

同一根因导致多个失败用例合并一个 Bug，保留映射；不同根因分别编号。严重性按实际影响和触发条件评定：数据损坏/泄露/录错主播、核心链路不可用、可绕过功能问题、显示体验分别说明理由，不一律高危。

Android 授权、单屏采集限制、平台登录/验证、手机厂商后台限制、暂时无在线源或没有 GPU，本身不必然是 Bug；错误状态、丢文件、无法停止、无限重试、无提示和无法恢复仍应独立判断。不要以“已知限制”掩盖实测缺陷。

### 6. 必须交付的结果

将以下内容放在你本轮独立 QA 目录，最终只打包报告、复现材料和必要脱敏证据，不打包运行时、模型、浏览器资料或完整用户数据。

#### BUG-REPORT.md

按顺序组织：本轮结论与构建→真实缺陷→已验证关键链路→失败用例/Bug 对照→历史 Bug 回归状态→代码审查候选→未测试/阻碍→限制与剩余风险→修复优先级→测试结束状态。

每个真实 Bug 使用 `VD281-001` 起的唯一编号，至少包含：

1. 标题、模块、严重性及依据、是否回归、受影响构建/环境和测试层级。
2. 输入/前置条件/参数、样例 SHA256、版本及 EXE/APK SHA256。
3. 最短可重复步骤，精确预期/实际结果，失败次数/尝试次数。
4. 时间戳、对应 case_id、截图/录像/日志/JSON 的相对路径；网络/并发问题给出事件顺序和必要请求/响应，凭据脱敏。
5. 有源码时给准确文件/行号/调用路径，区分证实根因与推测；纯黑盒如实写无源码，不编造行号。
6. 最小复现命令或脚本、样例生成方法、影响范围、绕过方式、修复建议和可客观判定的验收条件。

没有发现缺陷的区域同样说明实际验证范围；不要给出“软件绝对无 Bug”的结论。

#### TEST-MATRIX.csv

UTF-8，正确引用逗号/引号/换行，推荐列如下：

case_id,priority,module,title,artifact_sha256,test_layer,environment,preconditions,input,steps,expected,actual,status,bug_id,evidence,attempts,duration_seconds,reason
