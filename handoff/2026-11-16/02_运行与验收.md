# 运行、构建和真正的交付条件

## 先保留用户现场

先核对正式安装版本和最近失败的直播任务。日志、Cookie、配对密钥、手机序列号、签名流地址、回放都属于本机资料；读取排查不等于授权上传。备份设置与任务后再改。不要覆盖用户原片、清空列表、批量删旧文件或卸载手机应用来“重置解决”。同机 Android 更新需保留原签名，否则覆盖安装失败，卸载会影响应用数据。

正式安装和源码 `.local` 是两套数据。`--home` 只适用于启动器；源码直接运行使用环境变量。`start.ps1` 默认会使用源码 `.local`，新测试应明确隔离，不能无意接入正式资料。

## 同机隔离源码启动

本机现有打包运行库可复用，无需复制几 GB；先确认文件仍存在。以下命令在 `E:\VideoDesk` 执行，只用于新测试实例：

```powershell
Set-Location -LiteralPath 'E:\VideoDesk'
$env:VIDEO_DESK_DATA = Join-Path $PWD '.local\handoff-next\data'
$env:VIDEO_DESK_DEFAULT_OUTPUT = Join-Path $PWD '.local\handoff-next\output'
$env:VIDEO_DESK_PORT = '18976' # 先检查未被占用；占用则换一个空闲端口
$env:VIDEO_DESK_APP_ROOT = "$PWD"
$env:VIDEO_DESK_FFPROBE = Join-Path $PWD 'runtime-tools\ffprobe.exe'
$env:VIDEO_DESK_NODE_EXE = Join-Path $PWD '.local\build-exe\payload\runtime\node\node.exe'
& '.\.local\build-exe\payload\runtime\main\python.exe' '.\app.py'
```

打开 `http://127.0.0.1:18976/`。先查看运行组件报告。专用浏览器可能还需指定 `VIDEO_DESK_BROWSER_EXE` 为实际可执行文件（见 `integrations/login_browser.py`），不要凭空写路径。需要后台启动时使用 PowerShell `Start-Process -WindowStyle Hidden`，只管理自己创建的进程。

换机/干净源码：参照 `docs/BUILD.md`、`requirements-lock.txt` 和 `setup.ps1`，主打包 Python 固定为 3.13.17，MediaCrawler 使用独立 3.12，Node 22。源码安装脚本依赖工具已安装及联网；包内没有模型、运行环境或预编译 ffprobe，需按脚本准备。MediaCrawler 源码未随包携带，安装/构建按固定提交取得且保留其非商业许可。不要直接运行旧 `package_share.py` 或 `package_ai_handoff.py` 当成新交接，它们包含旧版本号/旧结构。

## 测试与构建入口

```powershell
# 开发依赖环境中执行；本机可用上面的 bundled python 完整路径替代 python
python -m unittest discover -s tests -p 'test_*.py'
node --test @(Get-ChildItem -LiteralPath tests -Filter '*.mjs' -File | ForEach-Object FullName)
```

Python 测试也要设置隔离 `VIDEO_DESK_DATA`。DSH 测试必须配置 `VIDEO_DESK_URL`、`VIDEO_DESK_TEST_VIDEO`、`VIDEO_DESK_TEST_OUTPUT`；缺前置跳过就报告跳过。`tests/test_bug_report281.py` 和 `Launcher281Harness.cs` 是上轮回归，不能充当当前可靠性验收。

PC：`scripts/build_windows_exe.py` 的 `prepare / bundle / all`，先读参数帮助。现有 `.local/build-exe` 有缓存和已备运行库，不要未经检查重下全部。C# 启动器需要合适编译器和授权有效的微软 CRT。APP_FILES 是显式清单，新增源码/网页文件需纳入。

Android：`scripts/build_android.py`，不是 Gradle 项目。当前脚本引用 SDK `build-tools/36.0.0` 和 `platforms/android-37.0/android.jar`，需要 JDK 的 javac/keytool。本机签名材料在 `.local/android-signing-key.jks` 和 `.local/android-keypass.txt`，只能本机使用，不随包外传。脚本目前硬编码 Android 发布名 1.1.1；若确实发新 APK，必须同步维护 Manifest 版本、显示版本、发布文件名和 PC 内含 APK。没有旧签名的换机开发者不能声称新 APK 能直接覆盖原应用。

## 接手后的验收门槛

1. **先复现用户失败。** 确认实际主播身份与当前正在开播，记录客户端/版本、前后台状态、配置和失败步骤。取得脱敏日志与失败前后的状态；不能只换一个能录的房间就宣称原问题解决。
2. **电脑真实录制。** 在桌面将要交付的那个构建上，走正常页面操作：开始、首字节、持续写入、停止、保存、完整解码和页面有声回放；重新启动后仍能找到回放。记录主播身份及实际音视频内容，而非推荐流。
3. **开播自动触发。** 至少完成一次真实的未开播→开播→自动写入闭环，记录检测延迟、是否要点确认、失败自动恢复和通知。真实事件未等到则保持待验收；受控源可补测状态机，不能冒充真实事件。
4. **手机真机。** 在用户 vivo 或明确记录的 Android 真机上验证多人独立录流；先两路同时持续录制，再验证所承诺上限，切主播和切 App 不串画面。屏幕录制作为单独的一路备用功能测试。录制结束可在手机有声播放。
5. **后台与持续运行。** 覆盖退后台、锁屏、Activity 重建、手机进程重启、电脑重启/断网恢复。至少 30 分钟实际连续录制，并计划覆盖两小时自动监控；时长及真实/受控来源如实记录。遇系统限制应在产品里明确当前可用状态和操作，不能展示假成功。
6. **USB 物理传输。** 真机录制完成后实际接线、自动传输，中途物理拔线再接、继续原偏移、校验、去重，电脑页面有声播放；手机原件保留。不能用脚本上传一个合成 MP4 替代这个验收。
7. **普通人操作。** 不依赖开发者控制台、ADB 命令或解释隐藏按钮，从新安装/升级后的主界面完成添加、开启自动录制、看到状态、停止和回放。只在系统实际要求时让用户确认权限，不重复发无关授权。
8. **最后才交付。** 修复源码、构建、实际安装包测试和桌面更新绑定同一 SHA256；保留用户任务/设置/原片。输出已实测、未实测、仍失败及必要条件；没有证据就不能标完成，更不能承诺“完美、没有 bug”。

这些是下一位 AI 的工作要求，不是本次已经执行的测试。当前没有再次测试手机或直播。
