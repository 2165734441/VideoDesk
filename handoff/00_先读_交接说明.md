**当前实现是 2.4.1；2.5 是待实施需求，不能当作已完成。本次仅制作交接包，没有实现 2.5 功能，也没有构建新版 EXE。**

请依次阅读本文件、`01_最新修改需求_2.5待实施.md`、`02_问题与测试记录.md`，然后进入 `项目源码` 工作。测试配置中的路径均相对于本交接包根目录。

## 项目是什么

映格 Video Desk 是在本机网页操作的视频工具，整合 yt-dlp/yt-dlp-ejs、MediaCrawler、dsh-video-storyboard、FFmpeg、ImageHash、本地 SenseVoice 和 OCR。已有链接采集、网页录制、规则抽帧、镜头分镜与台词对齐、AI 阅读包、分集合并、已有资料合并、图片去重等功能。

2.4.1 已完成启动兼容性修复：内置运行库、组件隔离检查、降级启动、检测并修复、启动诊断。新 AI 不应将这些工作重做或回退。2.5 的重点是分清操作用途、修复实际问题并验证，不是推翻原项目的镜头分析和台词对齐算法。

## 包内结构

- `项目源码/`：当前开发源码快照，包含网页、后台、启动器、插件、全部项目测试、构建脚本、锁定依赖、两个上游项目源码和许可；不是 Git 克隆，不含 Git 历史。
- `测试素材/2月21日.mp4`：用户明确同意随交接包携带的唯一视频。不要把它上传到外部服务，测试默认在本机执行。
- `测试配置.json`：样片相对路径、哈希、元信息和建议测试参数。
- `03_给下一个AI的开始指令.txt`：可以直接发给接手 AI 的任务。
- `04_打包验收记录.json`、`PACKAGE-MANIFEST.json`、`SHA256SUMS.txt`：包内文件检查、完整性及隐私边界记录。ZIP 本身的 SHA256 在 ZIP 外的同名 `.sha256` 文件中。

包内没有 Python/Node.js 大型运行环境、语音模型包、现成 EXE、用户账号、Cookie、浏览器资料、用户素材库、历史任务数据库、临时测试目录或其他私人视频。因此它是开发交接包，不是双击就可运行的离线安装包。

## 开发与测试启动

优先使用 Windows x64。Python 主环境建议 3.13；MediaCrawler 使用独立 Python 3.12 环境。Node.js 使用 22 或更高的兼容版本。源码安装需要联网获取锁定依赖；本地规则抽帧不需要平台账号。

在 `项目源码` 中，用已安装的 Python 创建虚拟环境并安装依赖：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

直接启动隔离开发服务，不连接或改动已经安装的映格数据：

```powershell
$env:VIDEO_DESK_DATA = Join-Path $PWD '.local\handoff-dev\data'
$env:VIDEO_DESK_DEFAULT_OUTPUT = Join-Path $PWD '.local\handoff-dev\output'
$env:VIDEO_DESK_PORT = '18976'
$env:VIDEO_DESK_FFPROBE = Join-Path $PWD 'runtime-tools\ffprobe.exe'
# 如果 Node.js 没有在 PATH 中，请填写实际位置：
# $env:VIDEO_DESK_NODE_EXE = 'D:\Tools\node\node.exe'
.\.venv\Scripts\python.exe app.py
```

打开 http://127.0.0.1:18976/ 。端口被占用时改为其他空闲回环端口，并同步修改 CLI 的 `--url`。FFmpeg 可由 imageio-ffmpeg 提供，也可用 `VIDEO_DESK_FFMPEG` 明确指定。语音模型需要在隔离工作台设置中另外安装；模型缺失不能当作“完整台词已验证”。OCR 依赖及模型状态须实际检查。

`start.ps1` 仍有检查版本为 `2.0.0` 的旧逻辑，本次未修改，交接测试请用上述直接启动方式。`setup.ps1` 是完整环境安装入口，但会初始化并获取 MediaCrawler Git 提交；交接包中的上游源码没有 `.git`，请先理解脚本行为，勿以安装脚本报错推断抽帧程序损坏。

项目测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
node --test tests/test_dsh_adapter.mjs tests/test_dedup_ui.mjs tests/test_progress_ui.mjs tests/test_sheet_limit.mjs
```

上游 storyboard 测试在 `third_party/dsh-video-storyboard/test`。部分上游测试、浏览器验收、语音和打包验证需要额外环境，不能仅凭基础测试通过宣称全部验收通过。`scripts/verify_*.py` 中的验收脚本有的会建立任务和输出，只能指向隔离数据目录。

## 代码入口

| 子系统 | 入口与用途 |
| --- | --- |
| 服务和任务 | `app.py`：FastAPI、任务状态、FFmpeg、旧接口、请求鉴权 |
| 本地来源 | `integrations/local_sources.py`：多选、发现文件夹、系统选择器、分块来源、校验 |
| 批次处理 | `integrations/batch_pipeline.py`：导出选项、分段、继续、汇总 |
| 分镜与台词 | `integrations/storyboard.py`、`storyboard_bridge.mjs` 与 `third_party/dsh-video-storyboard/src/storyboard/` |
| AI 阅读包 | `integrations/ai_package.py`、`ocr_session.py`、`ocr_worker.py`、`asr_worker.py` |
| 素材 | `integrations/material_history.py`、`material_packages.py`：文件归属、清理、资料合并 |
| 网页 | `static/index.html`，`app.js`、`workflow.js`、`local_sources.js`、`enhancements.js`、`episodes.js`、`materials.js` |
| 启动器与分发 | `launcher/`、`scripts/build_windows_exe.py`、`prepare_vc_runtime.py`、`package_share.py` |
| CLI 和插件 | `bin/video-desk.mjs`、`dsh-plugin/` |

网页多个脚本会覆盖先前定义的函数，共享 `exportSettings`，不能只改某一处按钮文字就认为流程已经分离。
