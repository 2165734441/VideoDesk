# 问题与测试记录

记录日期：2026-11-02。软件基线：2.4.1。本文不代表 2.5 已修复或已验收。

## 已实测复现：规则抽帧继承 AI 设置

操作使用独立的无头 Chromium 页面加载当前源码网页。GET 仅用于读取本机服务状态；所有非 GET 请求均被测试路由拦截并返回测试响应，没有创建真实生产任务，也没有改动正式素材或服务器设置。

复现步骤：

1. 准备旧版保存设置：`outputs.frames=false`、`puzzles=true`、`transcript=true`、`ai=true`，且 `ai_package.enabled=true`。
2. 打开网页，等待保存设置加载，进入规则抽帧页。
3. 页面仍展示“生成集中上传的 AI 阅读包”；同一页可见三个文件夹按钮：“导入本机视频文件夹”“导入文件夹”“网页选择文件夹”。
4. 加入一个测试来源并点击“直接抽帧”。检查拦截到的 `/api/batches` 提交。

实际提交关键字段：

```json
{
  "kind": "rules",
  "outputs": {"frames": false, "audio": false, "puzzles": true, "transcript": true, "clips": false, "ai": true, "zip": false},
  "ai_package": {"enabled": true, "combined": false, "screen_text": true, "ocr_threads": 2, "scan_seconds": 1, "batch_files": 10}
}
```

测试页面没有 JavaScript 未捕获错误。这是实际请求内容与用户用途不一致，不能通过修改页面名称或让用户手动取消勾选来算修复。

## 代码已确认，尚不等于完整现场复现

| 问题 | 证据 | 下一步 |

| 速度限制 | 多处 FFmpeg 固定两线程，OCR 限 1–2 线程，ASR 固定两线程，分镜取帧串行 | 引入资源档位，测量耗时与峰值内存，不减少信息 |

| 清理后观感 | 已有清理文件接口，但任务仍可留在列表，需统一清理后状态和默认过滤 | 多选预览、归属校验、默认移出及回收站失败处理 |

## 用户报告、尚未确认根因

- 本机播放器可正常播放，但导入后提示损坏或 FFmpeg 无法读取。
- 本机视频进入 AI 处理后暂停，无法继续。
- 解析或抽取较慢，尤其最后阶段缺少可理解的进度。

指定样片能被 FFprobe 读取，只证明容器头及轨道元信息可读。本次交接没有将该样片完整执行规则抽帧、AI 分镜、ASR、OCR、取消和恢复；这些必须由接手 AI 在隔离环境补测。不得把网页来源断线的理论分析直接当作用户暂停问题的已确认根因。

## 接手后的最小验收顺序

1. 核对清单和样片哈希，建立隔离数据与输出目录，记录版本和依赖状态。
2. 先复现设置串用，再修复流程隔离并证明仅抽帧不会启动 ASR/OCR/分镜。
3. 同一样片分别用本机路径、文件夹、网页选取和拖入测试，比较检查与实际处理。
4. AI 推荐流程完成全片分镜、台词与阅读包；台词或模型缺失要明确标记，不能空结果冒充成功。
5. 注入来源变慢、断线、识别子进程退出、取消和重试，核对恢复与其他任务可运行。
6. 比较性能档位的内容完整性和内存，检查清理不会触及原片及其他仍保留任务的资料。
7. 回归 CLI、插件和 2.4.1 启动修复，再构建与验证 2.5 发布包。
